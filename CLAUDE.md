## Architecture

This is an **offline-first Android inventory app** for MegasWeb, built with Flutter / Dart. The working directory for all Flutter commands is the project root (`megas-inventario-main/`). The `android/` subfolder contains only native Android build config.

### Two operating modes

The app supports two distinct backend modes, selected at first launch and stored in `ConfigService`:

| Mode | Backend | Config required |
|------|---------|-----------------|
| **API mode** (default) | REST API (Dio/HTTP) | `server_url` + `empresa_id` |
| **Legacy mode** | Direct DBF files via SMB2 | SMB host/share/path/credentials |

`ConfigService.isConfigured` checks different fields depending on mode. Legacy mode uses `empresaId = 0` as its namespace in all Drift tables.

### State and persistence

- **Local database**: [Drift](https://drift.simonbinder.eu/) (SQLite) singleton `AppDatabase` — all tables in `lib/database/tables.dart`, queries in `lib/database/database.dart`. Schema version is `3`; migrations in `AppDatabase.migration`. `lib/database/database.g.dart` is generated by `drift_dev` — re-run `build_runner` after editing `tables.dart`.
- **Config**: `ConfigService` wraps `SharedPreferences` — static getters everywhere; must call `ConfigService.init()` before use. Also stores display prefs (table font, size, bold, column visibility) and the legacy user list (`legacyUsuarios`).
- **UI state**: Riverpod `ProviderScope` wraps the app, but all screens use plain `StatefulWidget` with direct `AppDatabase` calls. Riverpod is wired but unused beyond setup.
- **Routing**: `go_router` with two named routes (`/`, `/config`); a redirect guard forces `/config` if not yet configured.

### Key data flow

1. **Sync (API mode)**: `SyncService` GETs `/articulos` (paginated 500), `/almacenes`, `/stock` and upserts into Drift tables. The `/stock` endpoint returns lot-level rows that populate `StockLotesLocal` (not `StockLocal`).
2. **Receive (Legacy mode)**: `LegacyService.recibir()` connects via `dart_smb2`, reads `ARTICULO.DBF` + `STOCKLOT.DBF` (and optionally `PARAMETR.DBF`, `PROVEEDO.DBF`, `FAMILIA.DBF`, `USUARIO.DBF`). Clears all `empresaId = 0` rows first, then creates 5 synthetic almacenes (1–5, since legacy DBF has no warehouse names), and populates the Drift tables. A `STOCK#_ART` snapshot is saved to `StockLocal` for use during send.
3. **Inventory session**: The user creates a `CabecerasInventarioLocal` header. Counted items are `LineasInventarioLocal` rows. Multiple lineas per article are supported for lot-level tracking.
4. **Send**: `SyncService.sendInventario()` POSTs to `/inventarios`; `LegacyService.enviar()` reads fresh DBF files, applies stock diffs (new − snapshot), appends `E_S_Alma.DBF` movement pairs ("INVENTARIO ANTES"/"INVENTARIO OK"), and writes files back over SMB.
5. **Edit article fields**: `AppDatabase.updateArticuloFields` updates barcode/peso/unicaj/unipal locally; `LegacyService.saveArticuloFields` additionally writes those fields back to `ARTICULO.DBF` over SMB.

### Stock display logic

`AppDatabase.getStockTotalPorArticulo` builds the per-article stock map in two passes: first populates from `StockLocal` (snapshot), then overrides with sum-of-lots from `StockLotesLocal` for articles that have lot-level tracking. Articles with lots always show the lot sum.

### DBF layer

`lib/services/dbf_service.dart` is a **pure-Dart xBase III+ parser/writer** with no native dependencies. Supports field types C/N/D/L, in-place updates (`setFields`), record appending, and key-based lookup (`findByKey`). All string fields use Latin-1 encoding (matching FoxPro/Harbour files).

Legacy article IDs are FNV-1a 32-bit hashes of trimmed/uppercased `CODIGO_ART`. Lot IDs hash `CODIGO_ART|CODIGO_ALM|CODIGO_LOT`.

### Screens and widgets

- `HomeScreen` — main inventory table (article list + filter/sort panel + bottom bar). Articles only render when an active (unsynchronized) session exists. Table columns and fonts are configurable via `ConfigService`.
- `LotEditorScreen` — per-article lot editor opened as a full-screen `Dialog` (not a route). Shows counted lineas and cached stock lots side-by-side.
- `ScannerScreen` — `mobile_scanner` camera overlay, returns a raw barcode string.
- `ConfigScreen` — first-run wizard and settings; switches between API and Legacy config forms.
- `AppToast` (`lib/widgets/app_toast.dart`) — shared overlay for non-blocking success/error messages.
- `FeedbackService` (`lib/services/feedback_service.dart`) — generates haptic feedback + Karplus-Strong synthesized audio (tap, scan, success, error tones computed at startup as raw WAV buffers).
